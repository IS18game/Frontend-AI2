## Задание 1. Валидация всех форм

В проекте покрыты валидацией все пользовательские формы:
- форма регистрации;
- форма входа;
- форма восстановления пароля;
- форма создания/редактирования промпта;
- форма создания шаблона;
- форма настроек профиля.

### Подход
Для удобства UX используется единый подход к валидации:
- проверка обязательных полей до отправки;
- проверка длины и формата данных (email, минимальная длина текста и т.д.);
- показ понятного текста ошибки рядом с полем;
- блокировка кнопки отправки, пока форма невалидна;
- сохранение введенных данных при ошибке, чтобы пользователь не заполнял все заново.

### Почему так
Такой вариант уменьшает количество случайных ошибок и делает поведение форм предсказуемым: пользователь сразу видит, что именно нужно исправить.

## Задание 2. GET-форма поиска с саджестом и debounce

Реализована GET-форма поиска по шаблонам промптов.

### Как работает поиск
- запрос отправляется только если введено **минимум 3 символа**;
- используется debounce (задержка перед запросом), чтобы не отправлять запрос на каждое нажатие клавиши;
- во время ввода показываются поисковые подсказки (саджесты);
- по нажатию Enter или кнопки поиска выполняется переход на страницу результатов.

### Почему GET
Поиск сделан через GET, чтобы:
- можно было делиться ссылкой на результат;
- состояние поиска не терялось после перезагрузки;
- работала предсказуемая навигация назад/вперед в браузере.

## Задание 3. Страница результатов поиска

Добавлена отдельная страница результатов поиска, например:
- `/search?query=marketing+email`

### Поведение страницы
- при открытии страницы чтение параметра `query` идет из адресной строки;
- результаты подгружаются на основе значения `query`;
- после перезагрузки страницы результаты сохраняются, так как ключ поиска хранится в URL;
- если `query` пустой или короче 3 символов, пользователь получает подсказку, что нужно ввести минимум 3 символа.

---

## Проверка

Что проверено вручную:
- все формы показывают ошибки при невалидных данных;
- GET-поиск не отправляет запрос, пока не введено 3 символа;
- подсказки появляются во время ввода и обновляются с debounce;
- страница результатов корректно открывается по URL с `query`;
- после обновления страницы результаты не сбрасываются.

### Быстрые ссылки для проверки
- Главная: `/`
- Регистрация: `/auth/register`
- Вход: `/auth/login`
- Восстановление пароля: `/auth/reset-password`
- Редактор: `/editor`
- Создание шаблона: `/templates/create`
- Настройки профиля: `/profile/settings`
- Поиск: `/search`
- Результаты поиска (пример): `/search/results?query=prompt`
